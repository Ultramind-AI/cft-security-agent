# Runtime Evidence v2

`Evidence` — единый контракт для статических и runtime-наблюдений. Он хранит
факты, полученные доверенным кодом, отдельно от краткого описания для человека
и от детерминированного вердикта.

```text
Hypothesis.id
  → Evidence.hypothesis_id
ActionProposal + ExecutionResult
  → Evidence.action
Проверенная возможность или runtime-проверка
  → Evidence.observation.facts
TargetProfile + RuntimeServiceMap
  → Evidence.scope
Сессия SandboxManager
  → Evidence.sandbox_session_id
Сохранённые записи исполнения и аудита
  → Evidence.artifacts
```

## Контракт Evidence

Поле `source` принимает значения `static` и `runtime`. Runtime-наблюдение
обязательно связано с `sandbox_session_id`: оно не может выдавать результат за
факт о неуправляемом хосте или production-цели.

`scope` фиксирует зарегистрированный target, окружение, сервис и точную
границу проверки: маршрут HTTP или область исходного кода. `artifacts` содержат
ссылки на сохранённые записи исполнения и аудита, поэтому наблюдение можно
проверить независимо от памяти текущего запуска.

`summary` предназначен только для отчёта и интерфейса. LLM не создаёт
`observation.facts` и не может заменить ими фактические данные или вердикт.
Вердикт формируется детерминированной возможностью после разбора сохранённого
результата Executor. Модели Evidence и вложенные объекты неизменяемы.

## Runtime HTTP-наблюдения

Возможность `observe_http_surface` выполняет только безопасный GET-запрос без
параметров. Она не использует обычный однократный путь Executor:

```text
одобренный ActionProposal
→ SandboxManager
→ управляемая сессия target
→ RuntimeServiceMap
→ SandboxRunner
→ Docker sandbox
→ observe_http_surface
→ сохранённый ExecutionResult
→ Evidence
```

`RuntimeServiceMap` разрешает запрос только к готовому зарегистрированному
сервису и его известному маршруту. Если Docker sandbox или карта сервисов
недоступны, проверка отклоняется; обращения к хосту или внешней сети не
используются как запасной вариант.

Worker не следует редиректам, не сохраняет тело ответа и не записывает значения
cookie. Из одного сохранённого HTTP-ответа формируются отдельные записи
Evidence:

- статус и категория ответа;
- выбранные заголовки безопасности;
- атрибуты cookie без значений;
- CORS-заголовки;
- параметры редиректа;
- классификация health/error-ответа;
- доступность известного маршрута.

Все записи одной проверки содержат одинаковые ссылки на сессию, действие,
исполнение и аудит. Это позволяет показывать наблюдения в отчёте или интерфейсе, не
выдавая сам факт HTTP-ответа за подтверждение уязвимости.
